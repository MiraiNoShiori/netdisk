# 功能补全设计

保留原有 API，新增能力不依赖前端框架。

## S3 与混合存储

同时装配 local 和可选 S3，读取按 blobs.backend 路由，默认后端只决定新写入位置。S3 使用 MinIO Go SDK；上传按固定 8 MiB 分片、单并发流式处理，下载通过可 Seek 的 Range 对象读取。合并按序打开源片，经 io.Pipe 交给 multipart 上传，失败取消管道和远端 multipart。

迁移先复制并核对 SHA-256 与长度，再用条件更新切换数据库指针，最后清理原对象。下载增加短时签名 URL，客户端可直接访问对象存储；既有代理下载继续支持 Range。签名端点需为客户端可访问的地址。

## NFSv3 网关

使用 go-nfs 实现 TCP NFSv3，将 billy 文件系统操作映射到同一 Files 业务层，不导出 blobs 物理目录。每个网关固定导出一个已认证用户的根目录；默认仅监听 loopback，显式配置允许的客户端 CIDR。NFSv3 AUTH_SYS 不是网盘账号认证，不信任客户端传来的 UID；一实例一用户。

随机写入使用临时磁盘文件，关闭时流式写回并原子替换节点的 blob；读取直接流式读取。当前定位是局域网演示网关，不承诺 POSIX 硬链接、符号链接、跨协议并发写入锁或高吞吐随机写；不支持的操作明确返回错误。

## P2P 新分享类型

独立的 /p2p/shares 管理与匿名信令 API，分享带 type=p2p。服务器只保存短期 SDP 信令和文件名/大小，不接收文件字节。浏览器通过 WebRTC DataChannel 直接传输，局域网无需 TURN；不配置中继，连通失败明确报错。信令房间有到期、容量与消息大小上限，发送端需要登录并校验房主用户 ID，接收端使用不可猜测的邀请 token。使用完整 ICE gathering 后的 SDP，避免候选积压。

演示页支持发送、接收、进度及取消；接收优先写入 File System Access API，兼容模式有明确文件大小上限，避免无限内存缓存。

新增可重复执行的数据库迁移命令、隔离 Compose 测试环境与 CI。验证真实 PostgreSQL、S3 Range/合并/迁移、NFS 协议操作、P2P 信令及浏览器直传。未实测的环境能力在验收记录中明确注明。
